# v0.1 plan (bootstrap deliverable)

This is the plan the bootstrap prompt asked for, kept as the record of how the work was scoped. It was written before implementation and then superseded by the instruction to build every release; the outcome of each item is in [release-status.md](release-status.md).

## Reconnaissance (at start)
- Working directory `/Volumes/Code/pl` was empty and sat inside an unrelated parent git repository (Cyberpod); no remote. A new private repository `vamsivarma27/proofloop` was created and the directory became its own repository.
- Toolchain: Node 25.8.1, pnpm 10.11, Git, `gh` 2.83.1 (authenticated), Claude Code 2.1.308, SQLite 3.51 (`node:sqlite`), Chrome installed.
- Verified against current official docs: plugin layout (`.claude-plugin/plugin.json`, `skills/` preferred over `commands/`, `agents/`, `hooks/hooks.json`, `bin/` on PATH, `${CLAUDE_PLUGIN_ROOT}`), `claude -p` interface (`--output-format json`, `--json-schema`, `--resume`, `--allowedTools`, `--disallowedTools`, `--permission-mode`, `--permission-prompts`, `--max-budget-usd`, `--settings`), PreToolUse hook contract (JSON decision, exit 2 blocks, `onFailure: block`), subagent/skill frontmatter, and that plugin subagents ignore `hooks`, `mcpServers`, `permissionMode`.
- `gh` has no sub-issue/dependency flags; GraphQL `addSubIssue` and `addBlockedBy` exist.
- Node `--permission` denies fs writes, child processes and network (network denial needs Node 25).

## Scope of v0.1
Plugin skeleton and setup; TypeScript CLI/engine and protocol schema; feature and bug protocols (sequential); reconnaissance and bounded context; plan artifact and approve/reject/edit gate; GitHub parent issue and checkpoints; SQLite run state; worktree isolation; gate runner for detected commands; status and resume; structured logs and evidence report. Excluded: greenfield construction, parallel agents, Cloudflare dependency, production deploy, broad performance testing.
